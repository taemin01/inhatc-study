Go 명령어
go mod init 프로젝트폴더명 -> mod 파일이 위치해야하는 디렉토리로 이동하여 go mod init loops 등과 같이 작성하여 mod 파일을 생성한다.
                            Go 모듈(프로젝트)을 초기화하는 명령어다.
                            해당 폴더(디렉토리)를 하나의 독립적인 GO 프로젝트로 만들어 go.mod 파일을 생성한다.
                            내부적으로 go.mod 파일에 모듈 이름과 go 버전을 기록해두고, 이후 패키지 의존성 go get을 자동 관리한다.
                            go 1.13 이상부터 기본 구조로 권장된다. go mod init ./ 같이 경로를 넣으면 오류 발생, 문자로 시작해야한다.
go run 파일명.go -> Go 소스 파일을 컴파일 + 실행까지 한 번에 수행하는 명령어다.
                   내부적으로 임시 디렉토리에 실행 파일을 생성한 후 바로 실행한다.
                   여러 파일을 함께 실행할 수도 있다. 그리고 외부 패키지를 사용하려면 반드시 go.mod가 있어야 한다.
                   즉 go mod init 으로 초기화를 해야 외부 패키지를 사용할 수 있다.
go build 파일명.go -> Go 코드를 컴파일만 해서 실행 파일 .exe 또는 바이너리를 생성한다.
                     내부적으로 Go 컴파일러가 main 함수를  찾아 실행 가능한 바이너리를 생성ㅎ나다.
                     같은 폴더에 main.exe or main(mac or linux)이 생성된다. (실행은 따로 해야함)
                     go build는 외부 의존성도 자동으로 포함시켜 빌드한다. 


리눅스 명령어
cp 원본파일 복사본파일 -> 이건 사용해봄 cp 원본경로 복사할경로 맥북 터미널에서 써봄 아마 키 파일 옮길 때 해본 듯
                       아무튼 파일 또는 디렉터리를 복사하는 명령어로써 cp main.go main_backup.go는 main.go를 main_backup.go로 복사한다.
                       옵션
                         -r : 폴더 복사할 경우 사용(recursive) / cp -r src/ backup/
                         -i : 덮어쓰기 전에 확인
                         -v : 복사 과정 출력
                        cp는 기존 파일을 덮어쓸 수 있으므로 주의해야 한다. 리눅스는 /로 윈도우는 \로 경로를 구분한다.

깃 명령어
git reset -> Git의 이전 커밋 상태로 되돌리는 명령어다.
             git reset --soft 커밋ID : 커밋만 되돌리고 변경 내용은 그대로 작업 폴더에 유지한다.(staging 상태 유지 -> add 상태를 말하는 듯)
             git reset --mixed 커밋ID : 커밋 + 스테이징 되돌리고, 파일 수정 내용은 남긴다.
             git reset --hard 커밋ID : 4주차 txt 파일에 있는 HEAD^, HEAD~n등 커밋 스테이징 작업 내용 전부 삭제한다. 강제로 되돌려버린다.
             이미 push 한 커밋을 reset 하면 remote와 충돌이 발생할 수 있다.
             --hard는 되돌릴 수 없으므로 신중히 사용해야 한다.
git merge 브랜치명 -> 다른 브랜치의 내용을 현재 브랜치에 병합한다.
                     git checkout main
                     git merge feature/login : feature/login 브랜치의 변경 내용을 main에 병합하는 과정이다.
                     충돌이 없다면 자동 병합이 되고 충돌이 있으면 수동으로 수정 후 git commit이 필요하다.
                     merge는 현재 브랜치 기준으로 병합 대상이 아니라 병합 받는 쪽이 현재 브랜치이다.


기타
.gitignore 파일 생성 (*.exe) -> 깃이 추적하지 않아야 하는 파일 목록을 작성하는 파일이다.
                               *.exe를 작성하면 해당 프로젝트 루트에 있는 .exe 파일은 전부 무시한다.
                               **/*.exe 이렇게 작성하면 특정 확장자의 모든 경로에 있는 것들은 다 무시된다.
                               **는 0개 이상의 하위 디렉터리를 의미한다.
